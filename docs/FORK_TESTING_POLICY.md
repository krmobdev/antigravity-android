# Правила развития и проверки форка Antigravity Android

Дата принятия: 21.10.2026. Основной проект: `krmobdev/antigravity-android`. Разрабатываем **свой форк**, не переписываем upstream без необходимости. Экспериментальная APK и стабильная версия — разные состояния; отсутствие рывков на телефоне ещё не является готовностью к публичному релизу.

## Перед изменением
1. Одна самостоятельная задача — отдельная ветка от актуальной версии форка; зафиксировать наблюдаемый симптом или требование и **проверяемые критерии принятия**.
2. Для воспроизводимого дефекта по возможности сначала написать тест, который падает на старом поведении, затем исправить причину. Диагностировать конкретные обработчики и события, а не делать серии неопределённых «оптимизаций».
3. Предусматривать отмену эксперимента без удаления пользовательских данных, смены `applicationId`, замены подписывающего ключа или сброса хранилища.

## Минимальный набор тестов для каждого изменения
- **Логика и граничные условия:** unit-тесты рядом с изменённым модулем, в том числе повторные события, отмена, исключения, ограничения диапазонов.
- **Связи компонентов:** integration/behavior-тесты, если затронуты React ↔ WebView ↔ Android ↔ Core; проверять жизненный цикл, фон/возврат и независимые состояния.
- **Регрессии:** существующий локальный набор тестов должен оставаться зелёным. Для scroll — проверять жесты в обе стороны, скорость, `touchcancel`, повторные свайпы, границы, торможение и отсутствие больших перескоков после задержки кадра.
- **Устройство:** перед утверждением UI/жестов провести ручной smoke-тест на Android, включая сценарий, который пользователь действительно считает сломанным; автоматика не заменяет визуальную проверку.
- **Готовность к релизу:** подписанный APK тем же ключом и совместимым `versionCode`; проверка `apksigner`, установки поверх прошлой версии и сохранности данных. Диагностические сборки не выдавать за релизы.

## Локальный набор команд (без GitHub Actions)
Из корня репозитория:

```sh
bash web/tests/selftest.sh
node web/tests/scroll_inertia_ab.test.cjs
node web/tests/scroll_diagnostics.test.cjs
git diff --check
```

`web/tests/selftest.sh` теперь включает unit-регрессии механизма прокрутки. При расширении проекта добавлять новые тесты в основной локальный запуск, чтобы не оставались «осиротевшие» тестовые файлы. Команды могут потребовать установленного `node`, `python3` и инструментов сборки.

## Управление рисками
- Никакой загрузки приватных ключей, паролей, журналов с токенами или пользовательских разговоров в GitHub. Временные `logcat`/Perfetto-артефакты хранить только локально и не коммитить.
- Не запускать GitHub Actions, пока лимит не восстановлен и владелец не подтвердит подключение CI. Тесты сначала запускать локально в Termux.
- Сохранять краткую запись «изменено → проверено → результат → известные ограничения» в PR/документации.
- В стабильную ветку попадёт только проверенное изменение без временных обработчиков диагностики и без регрессий.

## Текущий контрольный сценарий прокрутки
21.10.2026 пользователь подтвердил: собственная инерция поверх прямого перетаскивания пальцем устранила рывки и ощущается идеально. Для сохранения поведения зафиксированы значения `MAX_SPEED=3.2`, `MIN_SPEED=0.11`, `DECAY_MS=380`, `STOP_SPEED=0.025` и максимум шага кадра `34` мс в `web/scroll_no_native_fling_ab.js`.

Отдельная планируемая задача — настройки инерции в приложении: `docs/NEXT_UPDATE_TODO.md`. Пока это не настройка пользователя: константы закреплены как эталон и не должны меняться без тестов и нового пользовательского подтверждения.
