## Обзор

Долгие задачи программирования не должны терять уведомление о завершении и оставлять ложный индикатор «Working», когда Android приостанавливает Activity. Версия **v2.4.0-kr1** переносит в upstream v2.4.0 три проверенных исправления надёжности, сохраняя работу Core, Gateway, существующую авторизацию и остальные функции проекта.

У форка собственный Android package ID — **`com.krmobdev.antigravity`**. Он предназначен для установки параллельно с официальной `com.agy` и испытательной `com.agy.dev`. Данные приложений и состояние входа **разделены**: установка форка не переносит автоматически переписки, настройки или токены из двух остальных пакетов.

## Что нового

### 1. Нативные уведомления о работе агентов

Когда Activity свёрнута или остановлена, WebView может приостановить выполнение JavaScript или потерять поток наблюдения. Уведомление о настоящем завершении задачи не должно зависеть от активности вкладки интерфейса.

Новый **NativeAgentStateObserver** работает на стороне Android-сервиса и независимо подписывается на события состояния агента в Core. Для каждого разговора он отдельно отслеживает выполнение и считает его завершённым только при подтверждённых Core значениях **`IDLE` и `fullyIdle=true`**. Публикация происходит через Android NotificationManager, без чтения текста ответа и без предположений по DOM.

- Отдельные уведомления для нескольких одновременно выполняющихся разговоров, даже при одинаковых заголовках.
- Нажатие уведомления открывает соответствующий разговор.
- Раздельные каналы прогресса, завершения в открытом чате и фонового завершения.
- Сохраняемая очередь уведомлений, защита от повторов и повторная попытка доставки при временной недоступности Android.
- Интервал в пять секунд между **стоящими в очереди всплывающими уведомлениями**; открытый разговор не получает лишнего всплывающего баннера.
- Native Observer продолжает получать события Core после `Activity.onStop`, независимо от WebView.

### 2. Hca — восстановление потока агента

После сворачивания и повторного открытия приложения поток JavaScript иногда перестаёт обновляться, хотя сам агент продолжает работу. Это может выглядеть как зависший «Working».

При событии `agy:host-resume` обработчик **Hca** отменяет **только устаревшее транспортное наблюдение**, переподписывается и восстанавливает актуальный снимок состояния Core. Сама задача, родительский контроллер жизненного цикла и агент **не отменяются**.

В результате интерфейс продолжает показывать прогресс и завершение после блокировки/разблокировки и возвращения из фона, не запуская работу повторно и не дублируя итоговый ответ.

### 3. NDa / Sidebar — согласование состояний

Иногда старая сводка разговора продолжала показывать выполнение уже после подтверждённого завершения Core. Теперь при возвращении WebView обновляет поток сводок, а механизм согласования использует нативно подтверждённое `IDLE` прямо в настоящих React-компонентах sidebar версии v2.4.0.

- Настоящий работающий агент продолжает показывать **Working**.
- После завершения исчезает устаревший **Working**.
- Каждый разговор сохраняет собственное состояние, независимое от соседних задач.
- Новый достоверный `RUNNING` не скрывается старым свидетельством завершения.
- **Синие точки непрочитанного ответа не являются индикатором Working**. Логика прочтения upstream не изменена.

## Реальные испытания Android — 20 октября 2026 года

Интеграционные патчи испытывались на физическом Android-телефоне в пакете **`com.agy.dev`**.

- Настоящее задание Core завершилось после остановки Activity; зафиксировано Android-уведомление и корректный переход в нужный разговор.
- **Два разных агента Core одновременно находились в RUNNING около 45,5 секунды**, затем каждый завершился при остановленной Activity. Android сохранил **два отдельных уведомления**; дублей завершения и ошибок Native Observer не обнаружено.
- После запуска обычным значком, без нажатия уведомлений и просмотра ответов, оба завершённых разговора сохранили **синие точки непрочитанности**, при этом не осталось ложного **Working**.
- Длительный тест с Termux выполнил **10 последовательных `sleep 10`** с прогрессом от `10/100` до `100/100`. Пользователь дважды блокировал телефон и возвращался. Работа продолжилась, был получен ровно один итоговый ответ, индикатор выполнения исчез.
- Во втором тесте получен результат **`30/30`, `ГОТОВО`**. Журналы подтверждают `onPause/onStop/onResume` и последующее завершение Core. После выполнения вместо Working отображалась обычная временная метка. **Второе испытание не следует описывать как 50- или 100-секундное.**

**Важно различать:** перечисленные многозадачные и длительные испытания относятся к подтверждённой **Dev-интеграции**. Новая APK имеет отдельный package ID и release-сертификат: установка, порты Core/Gateway и подпись проверены; пользователь дополнительно подтвердил работу её нативных уведомлений. Авторизация именно в этом пакете отдельно не подтверждена.

## Проверка качества и целостности

Локальные тесты и проверки покрывают:

- **Java:** AgentTaskTracker, корректность состояний NativeAgentStateObserver, сохраняемую FIFO-очередь, интервал, повторы, повторную доставку, ConnectRPC и проверку Gateway.
- **JavaScript/React:** настоящие функции sidebar upstream v2.4, независимость статусов нескольких разговоров, переподписку и rehydration Hca, свежие сводки NDa и отбрасывание устаревших событий потока.
- **Python:** версионные вставки в staged web assets, генерацию конфигурации и проверку APK при сохранении оригинального `web/main.js`.
- **Android:** сборку в Termux, zipalign, `apksigner verify` (v2/v3), проверку отдельного package ID и флага `android:debuggable=false`.

**Границы доказательств:** при реальном испытании два агента завершились с интервалом около **14,8 секунды**, поэтому **пятиисекундная задержка FIFO** проверена контролируемыми и программными тестами, а не наложением двух настоящих завершений Core. Точную последовательность переподписки JS-потоков Hca/NDa проверили программно; пользователь и нативные журналы независимо подтвердили восстановление разговора и переходы Activity.

**GitHub Actions не запускались**, поскольку месячный лимит исчерпан. Автоматические триггеры релизного workflow специально отключены; успешное прохождение CI не заявляется.

## Установка и будущие обновления

1. После публикации скачайте `Antigravity-Android-v2.4.0-kr1.apk` и `SHA256SUMS.txt` из GitHub Release нашего форка.
2. Сверьте SHA-256 APK с файлом контрольных сумм.
3. На устройстве **ARM64 (arm64-v8a), Android 7.0+ (API 24+)** разрешите установку APK выбранному браузеру/файловому менеджеру и установите файл.
4. Откройте **Antigravity** и при необходимости выполните вход через внешний браузер. У приложения своё хранилище; для уведомлений потребуется разрешение Android.
5. Официальную Antigravity и Antigravity Dev можно оставить: идентификаторы пакетов различаются.
6. Следующее обновление ставится поверх этой же версии через APK с более высоким `versionCode`, подписанный **тем же постоянным сертификатом KR**. Удалять форк перед обновлением не нужно.

## Известные ограничения и планы

- Вибрация уведомлений зависит от системных настроек Android, каналов и пользовательских разрешений. Пользователь не ощущал вибрацию, однако её причина пока не установлена.
- Реальное столкновение двух почти одновременных завершений Core для проверки пятиисекундной очереди остаётся необязательным будущим испытанием. Программные тесты FIFO прошли.
- Длинный пользовательский промпт на снимках частично свёрнут или обрезан. Не установлено, является ли это штатным поведением upstream. **Фриз WebView не подтверждён.**
- Модель прочтения сохранена как в upstream. В будущем запланирована отдельная система, основанная на осознанном просмотре, а не просто открытии ответа.
- Для этого ручного выпуска нет результатов GitHub-hosted CI.
